# HeyClicky YouTube visual review — 12 October 2026

## Decision view

The supplied list contains 14 links but 13 unique YouTube IDs. All 13 unique videos were anonymously retrieved and visually reviewed across their full timelines. Combined runtime is **48:32**: 12 official HeyClicky videos total **16:22**, and the independent Startup Frank review is **32:10**.

The videos strengthen four priorities already present in `feature-plan.md`: screen-aware dictation, spatial selection, guided drawing, and persistent companions. They also add an important product lesson: HeyClicky's best interaction is a small companion over the current app, while consequential background work uses a separate, reviewable task card with **No / Adjust / Yes, do it** controls. OpenClicky should preserve its stricter Windows approval model and receipts rather than copy the demos' implied autonomy.

The independent review does **not** show HeyClicky autonomously editing a DaVinci Resolve project. It shows the reviewer selecting or showing UI, asking by voice, receiving spoken/text instructions and visual guidance, then manually applying edits. This is strong evidence for contextual teaching and weak evidence for reliable desktop execution.

## Evidence method and limits

- Retrieval used public YouTube streams through the Agent Reach documented `yt-dlp` route, without cookies, sign-in automation, or account access.
- Every official clip was inspected chronologically at one-second intervals, with a second full-timeline sheet at two-second intervals. The 32:10 review was inspected in six consecutive three-second action sheets plus a ten-second full-timeline sheet. These are sampled visual reviews across every timeline, not a claim that every encoded frame was examined.
- The action sheets preserve transient UI states closely enough to see selections, annotations, prompt/result cards, connector screens and task confirmations. The independent review's public English captions are retained as a secondary source for spoken wording.
- “Observed” below means visible pixels in the video. “Spoken claim” means narration or burnt-in captions without enough visual proof. Promotional editing, cuts and staged footage do not establish reliability on this Windows machine.
- Evidence folder: [`artifacts/research/heyclicky-2026-10-12`](../artifacts/research/heyclicky-2026-10-12/). Each ID has `*-full-timeline.jpg` and `*-action-detail-1s.jpg`; the long review instead has `*-action-detail-part-1.jpg` through `part-6.jpg`, covering 00:00–06:00, 06:00–12:00, 12:00–18:00, 18:00–24:00, 24:00–30:00 and 30:00–32:10. Timestamps inside each long-review part restart at zero, so use the part range for absolute time.

## Revised feature/build plan

This review changes ordering and acceptance detail, not the Windows safety baseline.

1. **Finish dictation acceptance first.** Use the existing local Whisper path and stable microphone selection. Add a Dictate destination with live words, raw transcript, optional context-aware rewrite and editable preview. Inspect the actual focused control before insertion and verify its final contents. Screen/context rewrite must never silently replace the user's original words.
2. **Turn region selection into a durable context object.** Store the selected pixels only for the active request, show the exact shared boundary, include window identity/revision and invalidate it on app change. Return grounded marks tied to that capture. Do not describe title guards as a security boundary.
3. **Complete the annotation vocabulary.** Add polygons, curved/freehand strokes and text labels using the existing overlay service. A mark must carry capture coordinates, monitor/DPI mapping, expiry and source revision. Keep this smaller than a general canvas.
4. **Build guided walkthrough state.** One instruction and one mark at a time, with Next/Back/Stop, an observed-result check and mandatory re-grounding after navigation. The DaVinci and FL Studio videos show why a sequence matters more than a dense answer.
5. **Make companions bounded and inspectable.** Create a companion through a short interview, then show its name, purpose, allowed apps/data, memory scope and deletion/export controls. Avoid automatic learning until explicit facts and boundaries are accepted with real use.
6. **Add routines only after companion acceptance.** A routine needs a proposed plan, schedule, account identity, scopes, per-run access snapshot, pause/run-now controls and a receipt. Confirm-each remains default. Auto/Full warnings and unchanged-running-task access snapshots remain mandatory; never enable Full access for the user.
7. **Connect one read-only account before multi-account actions.** The videos show the appeal of Gmail, Notion and Discord, but not isolation or failure handling. Start with visible account identity, least privilege, revocation, source links and no write scope. Add write actions only through the existing approval system.
8. **Defer mascot customization and referral/commercial surfaces.** A compact companion state can improve presence, but character packs, referral dashboards and brand films do not unblock the core Windows workflow.

## Acceptance derived from the videos

- Dictation: the live transcript matches speech; proposed rewrite and original remain reviewable; the inspected destination contains exactly the approved text.
- Spatial context: the visible selection matches transmitted pixels; changing window/page invalidates old targets; the returned mark lands on the requested control at mixed DPI.
- Walkthrough: each step names and marks one control; Next is disabled until the expected visible result or a deliberate skip; Back restores explanation without replaying an action.
- Companion: the user can inspect/edit purpose, memory and allowed sources; delete/export works; app-specific knowledge never grants broader action access.
- Routine/agent: No, Adjust and Approve are available before launch; account and scope are visible; running work cannot inherit a widened access mode; pause/stop works; outputs include sources and action receipts.
- Product claims: promotional clips, successful API calls, narration and logs are insufficient. Acceptance requires the visible destination state on Windows.

## Retrieval status

Initial public retrieval was blocked by YouTube HTTP 429/bot checks, and the installed Agent Reach executable itself failed to import `agent_reach`. Updating `yt-dlp` from 2026.06.09 to 2026.08.19 and using its official JavaScript challenge component restored anonymous access. No cookies or signed-in browser state were used. All 13 unique IDs then produced metadata and playable review-resolution video.
